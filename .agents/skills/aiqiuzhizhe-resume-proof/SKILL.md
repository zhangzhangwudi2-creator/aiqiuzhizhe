# aiqiuzhizhe-resume-proof

## 适用场景

- 把本仓库（AI 求职助手）的真实开发经历整理为简历条目。
- 面向岗位：AI 应用开发实习生、大模型应用开发实习生、AI Agent 开发实习生。

## 输入要求

- 原始经历描述或仓库文件（作为事实来源）。
- 用户对每条经历的参与程度确认：真实完成 / 参与开发 / 方案设计 / 技术调研。

## 事实边界（必须遵守）

- 区分四类参与程度，逐条标注：
  - 真实完成（代码已上线并验证）
  - 参与开发（与他人协作，说明自己负责的部分）
  - 方案设计（只做了设计或调研，未落地）
  - 技术调研（只看过文档或试过 demo）
- 调研过不等于熟练；没上线的功能不得写已实现或已上线。
- 不得编造：用户数、转化率、准确率、收益、团队规模、获奖、证书、合作方。
- 涉及数字必须能追溯到真实来源（测试结果、日志、仓库文件）；否则不写。

## 可突出的真实能力点（基于仓库代码）

- AI 应用落地：FastAPI 服务 + DeepSeek API 集成，单服务部署。
- Prompt 安全：不可信输入边界标签、注入防护、严格 JSON 输出约束。
- 结构化输出：Pydantic 模型校验 + 输出契约。
- 事实一致性校验：rewrite 结果防姓名、联系方式、学校、城市被替换（`fact_guard.py`）。
- 工程化：pytest 测试、GitHub Actions CI、离线质量评测、Railway 部署、IP 限流与缓存成本保护。
- 问题排查：线上冒烟、部署验证、限流/缓存/PDF 异常定位。

## 执行步骤

1. 读仓库关键文件，确认每条经历的真实来源（`main.py`、`prompts.py`、`fact_guard.py`、`quota.py`、`pdf_resume.py`、`tests/`、`README.md`）。
2. 与用户确认参与程度（真实完成/参与/设计/调研），不确定的标待确认。
3. 按"动词 + 做了什么 + 可核实结果或技术手段"写条目。
4. 技能分级：熟练 / 了解 / 接触，与证据匹配。
5. 输出简历条目 + 每条的事实来源 + 风险提示。

## 禁止事项

- 禁止编造任何量化成果。
- 禁止把了解或调研写成熟练或精通。
- 禁止写仓库中不存在的功能。

## 最终汇报格式

- 整理后的简历条目（可直接粘贴）
- 每条对应的事实来源
- 待确认项与风险提示
